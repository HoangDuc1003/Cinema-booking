## 2. Logic Chain

1. **R3 Manual Mode & Validation Enforcement**:
   - Observation 2 demonstrates that `updateHomeHero` currently validates manual selection by checking `Movie.countDocuments({ _id: { $in: ids } })` and throws `createHttpError(400)`.
   - R3 requires validating that all 5 movies are unique AND have ready native video trailers (`heroVideoStatus === 'ready'`). If invalid, it must reject with HTTP 422 (`Unprocessable Entity`).
   - Performing validation before `SiteConfig.findOneAndUpdate` ensures atomic preservation of previous config if validation fails.

2. **R3 Admin Hero Schema Alignment**:
   - Observation 3 shows `getAdminHomeHero` returns `{ settings, selectedMovies, availableMovies, rotation }`.
   - R3 requires returning `liveMovies` (current live 5 public movies), `manualSelection` (details of manual selection), and `rotation` (batch & rotation state).
   - Adding `liveMovies` and `manualSelection` while retaining legacy fields preserves frontend compatibility while satisfying R3.

3. **R4 Backend Identity & Metadata Transmission**:
   - Observation 1 shows `heroRotationService.js` populates `meta` (containing `configuredMode`, `effectiveMode`, `source`, `version`, `buildSha`, `deploymentId`, `environment`), but `showController.js` omits `meta` from `res.json()`.
   - R4 requires public response `meta` field to expose server identity and effective mode without leaking secrets. Adding `meta: payload.meta` to `showController.js` fulfills this requirement.

4. **R4 Admin Save Atomicity & Cache Refetch**:
   - `updateHomeHero` currently increments cache generation and deletes Redis keys, but does not execute an immediate GET refetch.
   - Calling `getPublicHomeHero()` immediately after cache invalidation warms the Redis cache and pre-calculates the updated ETag, ensuring zero-latency public GET requests following an admin save.

## 3. Caveats

- **Read-Only Scope**: In accordance with the assigned Explorer role, no source code files in `server/` were modified during this investigation.
- **TMDB Fallback**: Tests and runtime code fall back to local database movies when `TMDB_API_KEY` is not present or TMDB is unreachable.
- **Legacy Admin Fields**: `getAdminHomeHero` should retain `selectedMovies` and `availableMovies` alongside `liveMovies` and `manualSelection` to prevent breaking existing admin components during refactoring.

---

## 4. Conclusion

The current backend implementation provides a solid foundation for hero auto-rotation and manual mode, but requires specific, targeted refactorings to fully satisfy requirements R3 and R4:
1. `server/services/heroService.js`: Update `updateHomeHero` to validate 5 unique `heroVideoStatus === 'ready'` movies, throw HTTP 422 on failure, and trigger an immediate GET refetch after persisting and invalidating cache. Update `getAdminHomeHero` to return `liveMovies` and `manualSelection`.
2. `server/controllers/showController.js`: Include `meta: payload.meta` in the `getHomeHero` response JSON.
